# DAZN Bet in Scores — правила проекта

Этот файл читают все агенты: Claude Code напрямую, остальные через AGENTS.md. Правила одни на всех.

## О проекте
Кликабельный мобильный прототип ставок внутри приложения DAZN Scores (сначала Испания). Сейчас его показывают стейкхолдерам на звонках и дизайн-ревью. Позже — сторибук для разработки и юзер-тесты; сейчас это не в работе. Источник дизайна — Figma-файл DAZN-Bet-in-Scores (https://www.figma.com/design/JKfGVyF14eYu62ptYUkyzX/DAZN-Bet-in-Scores). Если прототип и Figma расходятся — права Figma.

## Владелец
Nik — продуктовый дизайнер, не программист. Говорить с ним по-русски, простым языком, в продуктовых терминах: что изменится на экране, а не diff. Уровень — как с арт-директором, без азов. Тексты интерфейса — на английском, юридические — на испанском как есть.
- Решение принято, только когда Nik сказал «ок».
- Перед записью в файлы-память (CLAUDE, PRD, TASKS) показывать точный текст.
- Вопросы по одному, с 2–4 вариантами и рекомендацией.
- Рядом с ID задачи — 1–2 строки, что она делает.

## Что читать первым
1. `notes/HANDOFF.md` — где мы, очередь, открытые решения.
2. `TASKS.md` — задачи и критерии «Готово, когда».
3. `PRD.md` — правила продукта (главный источник правды о поведении).
4. `STATUS.md` — что сделано и известные дыры.
5. `README.md` — как устроен `index.html` и система анимаций.

## Карта проекта
- `public/index.html` — весь прототип: токены и стили сверху, разметка, логика снизу. Карта по строкам — в README.
- `public/assets/img/`, `public/assets/fonts/` — картинки и шрифты.
- `build.py` — собирает офлайн-файл в `dist/` (не в git).
- Локальный просмотр: превью `prototype` из `.claude/launch.json` (порт 4173) или открыть `public/index.html` в Chrome.
- Онлайн: push в `main` → Vercel публикует за минуту. Вливание в main = публикация для стейкхолдеров.

## Роли чатов
- Продуктовый чат: ведёт PRD, TASKS, HANDOFF, готовит промты. Код не пишет.
- Чат разработки: одна задача — один новый чат «Dev · <ID> <название>».

## Процесс: быстро, одна задача за раз
1. Взять задачу из очереди в `notes/HANDOFF.md`. Прочитать её «Готово, когда» и Figma-фрейм.
2. Сказать владельцу в 1–2 фразах, что будет сделано, и сразу делать. Ждать «ок» только если задачи нет в TASKS или по ходу нужно решение о продукте.
3. Реализация прямо в папке проекта, малыми шагами. Отдельная worktree не нужна.
4. Самопроверка вживую вместо тестов: открыть прототип, пройти затронутый сценарий на 375 и 440, проверить соседние состояния в панели «Prototype states», убедиться, что в консоли нет ошибок, сверить с Figma-фреймом.
5. Ревью саб-агентом `reviewer` — один проход. Исправить блокирующее, остальное — одной строкой в отчёт.
6. Отметить задачу в `TASKS.md`, строка в `STATUS.md`, обновить «Очередь» в `notes/HANDOFF.md`.
7. Коммит с ID в начале («F2: …») и push в `origin main`.
8. Отчёт владельцу в 3 строки: что сделано, что глянуть на ссылке.

Два чата одновременно `public/index.html` не правят. Параллельно можно только то, что не трогает одни и те же файлы.

## Git
- В коммит — только файлы задачи. Не использовать `git add -A` и `git add .`.
- Перед началом — `git status`. Если там чужие изменения, сказать владельцу и не трогать их.
- Историю не переписывать.

## Нельзя
- Юридические тексты (предупреждение сверху, «+18. Juega con responsabilidad. Publi.», текст под итогом): не переписывать, не переводить, не сокращать.
- Шрифты DAZN Oscine: не менять, не заменять, не выносить за пределы проекта.
- Новые токены не добавлять. Использовать существующие; если подходящего нет — остановиться и спросить.

## Сначала спросить
Правки в Figma, изменение правил продукта из PRD, настройки Vercel и репозитория, удаление экранов и готовых состояний.

## Правила качества
- Анимации — только через токены движения (`MOTION TOKENS` в CSS, `SOFT` и `T` в JS), без новых чисел.
- Значения компонентов менять в блоке токенов, не в строке.
- Готовые состояния панели должны давать одни и те же цифры при каждом показе.
